# 6. 团队协作要求

**维护原则：每轮只「修改」既有文件、默认不「新建」。**
- 每轮工作只更新既有的记忆（`memory/` 各主题文件 + 索引 `MEMORY.md`）与进度（`progress/PROGRESS.md`），**不要**随手新建重复/冗余文件（含乐享侧镜像页面，避免重复建页，见 conventions 踩坑）。
- **先更新、确有必要才追加**：每轮结束提交进度/记忆时，若某条记录已存在（同一主题 / 同一天 / 同一轮），应**先就地更新**原条目内容，避免反复另起新行造成重复堆积；确属新主题 / 新阶段才**追加**新条目。
- 仅当确实新增主题 / 新阶段时，才在仓库与乐享两侧同步新增对应文件/页面，并同步维护 `memory/MEMORY.md` 主题索引，保证两侧镜像一致。

**每位成员在每轮修改完成后，必须同步两份工作文档：**
1. **进度 PROGRESS.md**（仓库 `progress/PROGRESS.md` + 乐享团队知识库 `progress/` 页）——把本轮进展、提交 hash、待办登记进"变更日志"，让下一位成员可续接。
2. **记忆**（仓库 `memory/` + 乐享团队知识库 `memory/` 同构拆分）——把本轮产生的稳定知识（新约定/新架构要点/新踩坑）沉淀进对应主题文件/页面。

**乐享镜像已获"自动同步、免逐一确认"授权（2026-09-07 起，替代原网盘镜像）：**
- **协作镜像只保留两处：仓库 `leo/dev`（权威源）⇄ 乐享团队知识库「silicon」（项目资产镜像）**；原项目网盘（Drive）上的 memory/progress 镜像已**退役**，不再作为同步目标。
- 每轮代码/文档修改完成后，由当轮成员**自动将改动的记忆与进度页级镜像到乐享**对应页面（`memory/` 主题、`progress/PROGRESS.md`），**无需再逐次询问**。
- 乐享是**页级在线读改写**（`block_fetch_page`/`block_update_page` 或 `entry_import_content`），普通成员对页面有编辑权即可更新，不存在网盘那种 `can_delete` 缺失 / 同名 `.md` 覆盖不命中 / 无在线内容编辑接口的权限坑；常规同步通过读取乐享页面与仓库文件对比校验一致。
- 仅当遇到**无法自行解决的异常**（如建页后内容与仓库不一致、需他人介入）才上报沟通。

> 具体执行路径与"同步到乐享团队知识库"的操作方式，以项目根 `README.md`"团队协作要求"一节为准。
> 记忆文件组织：本目录（`memory/`）按主题拆分，仓库 `leo/dev` 与乐享团队知识库「silicon」各持一份同构副本、互为镜像；无根级单文件权威副本。
