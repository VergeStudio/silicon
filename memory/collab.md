# 6. 团队协作要求

**维护原则：每轮只「修改」既有文件、默认不「新建」。**
- 每轮工作只更新既有的记忆（`memory/` 各主题文件 + 索引 `MEMORY.md`）与进度（`progress/PROGRESS.md`），**不要**随手新建重复/冗余文件（含资产侧每次覆盖上传触发的同名 `.md` 新条目，见 conventions 踩坑）。
- **先更新、确有必要才追加**：每轮结束提交进度/记忆时，若某条记录已存在（同一主题 / 同一天 / 同一轮），应**先就地更新**原条目内容，避免反复另起新行造成重复堆积；确属新主题 / 新阶段才**追加**新条目。
- 仅当确实新增主题 / 新阶段时，才在仓库与资产两侧同步新增对应文件，并同步维护 `memory/MEMORY.md` 主题索引，保证两侧镜像一致。

**每位成员在每轮修改完成后，必须同步两份工作文档：**
1. **进度 PROGRESS.md**（仓库 `progress/PROGRESS.md` + 项目资产 `progress/PROGRESS.md`）——把本轮进展、提交 hash、待办登记进"变更日志"，让下一位成员可续接。
2. **记忆**（仓库 `memory/` + 项目资产 `memory/` 同构拆分）——把本轮产生的稳定知识（新约定/新架构要点/新踩坑）沉淀进对应主题文件。

> 具体执行路径与"同步到项目资产"的操作方式，以项目根 `README.md`"团队协作要求"一节为准。
> 记忆文件组织：本目录（`memory/`）按主题拆分，仓库 `leo/dev` 与本项目资产各持一份同构副本、互为镜像；无根级单文件权威副本。
